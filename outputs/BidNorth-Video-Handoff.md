# BidNorth Video Handoff

## 1. One-sentence product description

BidNorth is a demo pre-bid readiness workspace for Canadian SMEs that compares a company’s declared evidence with illustrative tender requirements, identifies evidence gaps, and gives a gated next-step plan before proposal work begins.

## 2. Core promise and boundaries

- **What BidNorth does:** It calculates a deterministic, supporting readiness score and—more importantly—a readiness outcome gated by mandatory requirements; it maps each requirement to declared company evidence, source context, and a next action.
- **What it does not do:** It is not a live tender-discovery service, proposal-writing service, partner marketplace, tender-submission service, or professional/legal review tool. It displays a fixed set of 12 in-product tender records and links only to portal entry points.
- **Winner prediction:** No. The product repeatedly says it does not predict awards or award outcomes.
- **Legal/procurement eligibility:** No. “Verified” means matched to the declared company profile, not independently certified. The Coach says: “Guidance only. No eligibility determination, legal advice, or award prediction.”
- **Bid submission:** No. The methodology and exported plan say BidNorth does not submit bids.
- **Tender requirements and sources:** All tender records, requirements, section references, buyers, titles, dates, tender numbers, weights, and portal associations are **illustrative demo content**, not live solicitations. Portal links are entry points, not matching-record links. The product says no live notice has been accessed or synchronized.
- **Current disclaimers:** “Demo tender dataset”; “Demo tender record”; “Sample requirement reference”; “Illustrative requirement in this demo record; no official package has been reviewed”; “The original tender remains authoritative”; and “Always verify details in the original notice.”

The readiness gate is deterministic: a mandatory **Hard stop** yields “Do not commit proposal resources yet”; a mandatory **Missing evidence** or **Needs human review** yields “Fix gaps before committing proposal resources”; only all mandatory **Verified** items yield “Ready to prepare a bid.” The secondary score cannot override that gate.

## 9. Technical/demo preparation

- **Required environment variables:** None for core functionality. `DEEPSEEK_API_KEY` is optional and must remain server-side; it enables the optional DeepSeek coach call. The `.env.example` says the app works fully without it using deterministic coaching.
- **Works without AI key:** Yes. This is the recommended recording configuration.
- **Reset local state:** The saved profile key is `bidnorth.company.v1` in browser localStorage. Clear that key/site data or use an incognito/fresh browser context. The sample URL independently uses the default fictional company and preserves any saved profile.
- **Run:** Node.js `>=20.9.0` (README recommends Node 22). Run `npm install`, then `npm run dev`; open `http://localhost:3000/about`. In this PowerShell environment use `npm.cmd` if script execution blocks `npm.ps1`.
- **Recommended pre-open route:** `http://localhost:3000/about`, then use the on-page sample CTA rather than typing the sample URL; it communicates the intended journey.
- **Known limitations:** fixed local dataset; portal links are generic entry points; no live synchronization; no authentication/back end beyond the optional coach request; profile persistence is browser-local; task checks are current-session state; no file/document evidence upload; no bid submission; no legal/procurement eligibility determination; no award prediction.
- **Visible demo disclosures:** sidebar “Demo workspace v1.0”; footer “Demo tender dataset”; tender “Demo tender record”; “Fictional sample company · saved profile unchanged”; “ILLUSTRATIVE DATA”; source-panel “Public notice portal · illustrative record”; “No live notice accessed”; Coach “Demo tender record”; and Methodology’s full 12-record disclosure.

## 10. Evidence gaps or inconsistencies

1. **About-page ledger counts conflict with the actual sample ledger.** The hero/transition/product visual focuses on four rows and says “02 / 04 VERIFIED” / “2 requirements verified,” while the live sample has five mandatory requirements, three verified (registration, insurance, coverage), one missing-evidence project requirement, and one human-review security requirement. The product-window claim “Two mandatory items are not yet verified” is compatible with the live ledger; the four-row verified count is not a complete ledger count.
2. **The primary CTA’s sample company is not the same as a saved workspace company.** This is correctly labeled after navigation but should be said clearly in a pitch; the public journey demonstrates Northern Grid Solutions, not a visitor’s saved company.
3. **“Open official tender portal” is misleading.** It opens a generic CanadaBuys or Ontario Tenders entry page, not the named tender. The code/product otherwise correctly calls these portal entry points.
4. **The profile privacy copy says “when configured, OpenAI,” but the actual implementation calls DeepSeek.** This is an incorrect visible vendor label and should be fixed before recording.
5. **The 20–30% PSPC-contract-value claim has no direct visible source.** It sits near two cited links but neither is explicitly attached to the statement. Do not use it as a sourced fact in the video until sourced.
6. **All apparent procurement metadata is illustrative.** Names such as Natural Resources Canada and actual portal brands can look live, but titles, buyers, deadlines, tender numbers, requirements, weights, and source references are expressly demo content. Make the demo labels visible during recording.
7. **“Verified” can be misunderstood.** It is only a match to self-declared profile data. The UI does disclose this, but presenters should never say requirements are verified by BidNorth or the government.
8. **No supporting-document upload or independent validation exists.** The app records declarations, reference-prepared checkboxes, and simple fields only.
9. **The supporting readiness percentage is not a win likelihood.** It blends fixed weights and local rules; the outcome gate can disagree with a high score. Avoid leading with 83% without immediately explaining its supporting role.
10. **The Coach is labelled “AI analysis · DeepSeek” only when an optional external key works, but its accepted output is constrained to the deterministic approved guidance.** Live API use adds avoidable latency/failure and does not create novel live tender analysis.
11. **The public copy says “decision-before” and “ledger-” without a space after the hyphen.** These are visible punctuation/typography defects.
12. **The overview greeting is time-invariant.** It always says “Good morning,” regardless of local time.
13. **Deadline labels become stale with time.** Dates are fixed 2026 demo dates and list labels use the current browser date to render “days remaining” or “Closed.” Record promptly or avoid emphasizing relative-day wording.
14. **The public source links target future-dated/coded reference paths from the current project context and were not independently validated in this audit.** Treat them as displayed citations, not verified research links.
